# Manifold v0.3.0

Manifold v0.3.0 replaces OpenViking, INITE Brain and SurrealDB with an index
inside the Manifold process. The stack is one container of 15.6 MB. On a
synthetic corpus the size of production it peaked at 143 MiB of memory and
settled at 50 MiB; the previous stack used about 10.2 GiB idle in production.
See [performance](../performance.md).

## What changed

- `index.db`, a second SQLite file beside `manifold.db`, holds document chunks,
  extracted entities, facts and relations, FTS5 tables and int8 vectors
  (sqlite-vec, cosine distance).
- Extraction makes one structured chat call per section of at most 12,000
  characters, up to four at once, and keeps only grounded facts. Entities
  resolve by name and alias; `status`, `os_version` and
  `code_memory__default_value` keep one current value per entity.
- A missing `index.db` is seeded from `manifold.db` at start, without model
  calls for revisions already extracted. The embedder fills vectors in the
  background; a call the provider answers ends its backoff after a failure.
- The runtime image is distroless and has no shell. The healthcheck is
  `manifold healthcheck`.
- Configuration: `MANIFOLD_INDEX_DB_PATH`, `MANIFOLD_EMBEDDING_DIMENSIONS`
  (512), `MANIFOLD_PROVIDER_TIMEOUT` (3m), `MANIFOLD_EXTRACTION_TIMEOUT` (30m),
  `MANIFOLD_EXTRACTION_CONCURRENCY` (4). The OpenViking, Brain and SurrealDB
  variables, `MANIFOLD_HTTP_TIMEOUT`, `MANIFOLD_BRAIN_*`,
  `MANIFOLD_OPENVIKING_WRITE_TIMEOUT` and `OPENAI_EMBEDDING_DIMENSIONS` are no
  longer read.
- `status.components` reports `sqlite`, `index` and `provider`. Search hits
  report `semantic` or `graph` as their source, and `degraded_dependencies`
  uses the same names, instead of `openviking` and `brain`. The protocol
  revision stays 2: the skill does not depend on these values.
- Go 1.27.4, Node 26.13.1, Huma 2.41.0, `golang.org/x/crypto` 0.59.0,
  `modernc.org/sqlite` 1.63.0. See [the dependency audit](../dependencies.md).

## Upgrade

Start this release on the existing `manifold-data` volume; it migrates the data
of every release since v0.2.0 by itself. It seeds the index from
`manifold.db`, then extracts again the documents whose graph only the old
Brain held (all documents of v0.2.x), indexes API facts that never reached the
graph, and retracts derived records that an earlier retraction failed to
withdraw. See
[Upgrade from an earlier release](../operations.md#upgrade-from-an-earlier-release).
The release never opens the old `openviking-data`, `brain-cache` and
`surrealdb-data` volumes, so they remain a rollback point until they are
removed on purpose. `DATA_VERSION` is 6, so the production deployment broker
stops at this boundary for the operator's profile change.

After the server reports `0.3.0`, update the globally installed skill:

```bash
npx skills update manifold --global
```
